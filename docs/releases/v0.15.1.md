## Mnemosyne 0.15.1

### Everything in a summary can be changed
- **Edit a summary by hand.** Edit, next to Copy on the Summary tab, opens the whole summary: its text, topics (the tags at the top), decisions, action items (text, owner, due date, done), chapters, open questions and client facts. Add, remove and reorder items; each decision, item and question keeps its link to where it came up in the transcript. A meeting without a summary offers "Write a summary yourself".
- **Earlier summaries are kept and can be restored.** Versions, next to Edit, lists the summaries a meeting had before (replaced, edited or restored) and puts one back, with its topics and items. Done ticks, issue links and due dates carry over.
- **Revise with an instruction.** Under Re-summarize, ask for "shorter", "focus on the decisions" or "say who owns what": the model rewrites the current summary, your edits included.
- **Re-summarizing asks first** when the summary was edited by hand. The summary says when it was edited, and by whom.
- **Rename or merge a topic across meetings** from the Topics view. Summaries made later use the new name too.
- **Edit tasks from the Tasks view**: text, owner and due date, with the pencil next to a task.
- **The follow-up draft can be saved** after editing it.

### A window that keeps drawing
- On NVIDIA the window could freeze for good during or after a recording, or after switching workspaces: it took clicks but showed nothing new, and only a restart helped. The AppImage now runs natively on Wayland in a Wayland session. If a start on Wayland ever fails, the next start uses X11 by itself; `MNEMOSYNE_X11=1` chooses X11 and `MNEMOSYNE_WAYLAND=1` tries Wayland again.
- On X11 the window no longer waits on the compositor between frames, the likely cause of the freezes.
- **Redraw window**, in the tray (or `mnemosyne --redraw`), rebuilds the window in place if it ever stops drawing anyway.

### Fixes and speed
- **Transcribe appears as soon as a recording is saved** (with auto-transcribe off it only appeared after opening the meeting again).
- **Live copilot notes are about five times faster** with reasoning models such as Qwen3 (they no longer think before each update), so they keep up during a meeting.
- **Less memory while idle.** The backend no longer keeps a pool of PyTorch compile workers (one per CPU core) alive, and hands memory back to the system after unloading the speech models.
- **The built-in summary model summarizes long meetings in parts** that fit its context.

### Install
The app offers this update itself if you run the AppImage, deb or rpm. Otherwise download the AppImage (`chmod +x`, then run), the offline AppImage, the `.deb`, the `.rpm` or the `.flatpak` (`flatpak install --user <file>`). Verify downloads with `sha256sum -c SHA256SUMS`.
