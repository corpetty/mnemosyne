## Mnemosyne 0.4.1

### Important fix: system audio was recording the microphone
Selecting an output device ("system audio capture") did not record what your speakers play. The app asked PipeWire for a `<sink>.monitor` node, a PulseAudio-style name PipeWire does not resolve, so the recorder silently fell back to your default microphone. Recordings still contained the other people when they came out of your speakers, but only as your mic heard them, and "mic" and "system" were effectively the same audio (which also looked like speaker bleed).

System audio is now captured from the output's own monitor ports. If you record calls without headphones, expect much cleaner remote audio, better speaker separation and fewer duplicate lines. Sessions recorded before this release are unaffected on disk; re-transcribing them will not recover the remote audio that was never captured.

### New
- **rpm package** for Fedora and other RPM distributions.

### Fixes
- Package dependencies now name the PipeWire tools the app actually uses: `pipewire-utils` on Fedora (`pw-record`, `pw-dump`, `pw-cli`), `pipewire-bin` on Debian/Ubuntu. The rpm accepts either `ffmpeg` or Fedora's `ffmpeg-free`.
- Audio devices are targeted by name rather than by numeric id.

### Install
AppImage (`chmod +x`, then run), `.deb`, or `.rpm` (`sudo dnf install ./Mnemosyne-0.4.1-1.x86_64.rpm`). Verify downloads with `sha256sum -c SHA256SUMS`.
