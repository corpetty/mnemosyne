## 1. GPU install check in CI

0.8.0 put NeMo (a pinned GitHub tarball) into the `gpu` extra; nothing in CI installs that extra.
A GPU-less runner can still install it and import everything (CUDA wheels install without a GPU).

- New job in `.github/workflows/ci.yml` (on pushes that touch `backend/pyproject.toml` or
  `backend/uv.lock`, and weekly): `uv sync --locked --extra gpu --extra onnx` on ubuntu-22.04 with a
  cold cache, then `python -c` importing `torch, whisperx, pyannote.audio, nemo.collections.asr,
  onnx_asr` and building (not loading) each diarizer through `registry.build_diarizer` for
  `pyannote`, `nemotron`, `auto`. Free disk first (the runner has ~14 GB; torch + CUDA libs are
  ~6 GB): remove `/usr/share/dotnet`, `/opt/ghc`, `/usr/local/lib/android`.
- Same check as a step in the Release workflow before `bundle`, so a broken extra never ships.

## 2. Nemotron for live speaker labels

**As built:** instead of driving Sortformer's streaming step (offsets, feature context and
speaker cache by hand), the live transcript re-runs the normal Nemotron diarizer on everything
recorded so far every 30 s (a 38-minute meeting takes ~4 s) and corrects the live lines
(`transcription/live_rediarize.py`, `live_labels` events). Clustering still labels new lines
instantly; each pass keeps the labels people already saw and renames the clusterer to agree.

Live labels today: pyannote embeddings per committed line + online clustering
(`transcription/live_speakers.py`), then voice-profile naming. Nemotron (Streaming Sortformer v2)
is built for streaming. On machines where the final diarizer resolves to Nemotron:

- `transcription/live_speakers.py`: a `StreamingDiarizer` path next to the embedder: feed the live
  buffer's new audio to Sortformer's streaming step (read `diarizers/nemotron.py` for how the model
  is loaded; use its streaming API with a small chunk, keeping state between ticks), get per-frame
  speaker activity, and label each committed segment (per word when words exist, reusing
  `assign.py`) with the local speaker index.
- Names: Sortformer speakers are anonymous; keep mapping them to voice profiles with the existing
  embedder (one embedding per speaker once it has ~3 s of speech), so live names still appear.
- Selection: `live_diarizer` setting `auto | nemotron | embeddings`; auto = Nemotron when the final
  diarizer would be Nemotron. Falls back to embeddings on any load/runtime error (logged once).
- Keep CPU/GPU cost bounded: run the streaming step in `asyncio.to_thread`, respect
  `live_adaptive` (item 3 of 0.8).
- Tests with a fake streaming model (no NeMo in tests). Offline evaluation: feed AMI ES2004a
  (`~/.cache/mnemosyne-trials/ami/`) through `LiveTranscriber` with cached Parakeet segments and
  compare live speaker accuracy, embeddings vs Nemotron streaming; put the numbers in the commit.

## 3. Name the speakers

After transcription, a card on the Transcript tab (only when some speakers are unnamed
`SPEAKER_nn` / `Speaker n`): one row per unnamed speaker with talk time, a play button for their
longest clean turn (≤ 8 s, uses the existing player; never autoplays), a text field with
suggestions (calendar `attendees` not yet used as a name in this meeting, then voice-profile
names), and "Save voice" checked by default (enrolls via the existing rename + enroll path in
`services/speaker_service.py`). "Done" renames all at once (one transcript update, one
`summary_stale` flip). Dismissable per meeting (stored in the session: `speakers_reviewed`).

## 4. Share a quote

Select lines in the transcript (shift-click range, or a line's menu → "Share from here") →
"Share quote": `POST /api/sessions/{id}/clip {first_idx, last_idx}` → job cuts that span of the
mixed audio with ffmpeg (0.3 s padding, Opus) into `<data>/clips/`, returns text with speakers
and time (`> **Ana** [12:31]: …`) plus the clip path. UI: copy text, save the audio file (Tauri
save dialog; browser download), or open the folder. Clips count in the storage report and are
deleted with the session.

## 5. Due dates on action items

- Summary prompt: `action_items[].due`: an ISO date when the transcript gives one ("by Friday",
  "end of month"), resolved against the meeting date (give the model the meeting's date and
  weekday). Parser accepts ISO dates only; anything else → null. Carry over like `done`.
- Tasks: show due dates, sort open tasks by due date, "overdue" in red; filter "due this week".
- Trackers: pass `due` to GitHub (in the body), Linear (`dueDate`), Jira (`duedate`).
- Obsidian export: `📅 YYYY-MM-DD` (the Tasks plugin format) after the task.

## 6. Report a problem

Settings → General → "Report a problem": a dialog with a short description field, the diagnostics
text (editable, so the user can remove anything) and "Open on GitHub", which opens
`https://github.com/corpetty/mnemosyne/issues/new?title=…&body=…` in the browser. GitHub URLs are
limited (~8 kB): when the body is longer, copy it to the clipboard, open the new-issue page with
a short body saying "paste the diagnostics here", and say so. Nothing is sent by the app itself.

## 7. Offline installer

A second AppImage flavour, `Mnemosyne_<v>_amd64-offline.AppImage`, carrying a pre-filled uv cache
and Python for the base install (not the GPU extra: too big), so first launch works without
network. `scripts/build-all.sh --offline`: after the normal build, `uv sync` the base extras into a
throwaway venv with `UV_CACHE_DIR=<appdir>/uv-cache`, prune the cache (`uv cache prune --ci`),
download the managed Python into `<appdir>/python`; lib.rs: when these directories exist, pass
`UV_CACHE_DIR` (read-only copy: `--offline` + `UV_PYTHON_INSTALL_DIR`) to the first `uv sync`.
Release workflow builds and smoke-tests it too (smoke with networking cut for the install step:
`unshare -n` or an unroutable proxy). Updater keeps pointing at the normal AppImage.

## 8. Encryption at rest (opt-in)

Settings → General → "Encrypt meetings on this computer". Key: random 256-bit, kept in the Secret
Service keyring (`keyring` package; unlocks with the login session). On enabling, show a recovery
key once (base32, copy/save) and require confirming it: without it a lost keyring means lost
meetings.

- Database: SQLCipher (`sqlcipher3-binary` wheel), `PRAGMA key` on open; enabling migrates via
  `sqlcipher_export`, disabling back. FTS and vectors live in the same database.
- Audio: recordings and clips encrypted after stop (`<file>.enc`, AES-256-GCM in 64 KiB chunks with
  per-chunk nonces, so `GET /api/audio/file` can decrypt a range without reading the file).
  Transcription and live code decrypt to `$XDG_RUNTIME_DIR` (tmpfs, removed after). The WAVs
  pw-record writes during recording are plain until stop (documented).
- Not encrypted: Obsidian export (the user's vault), config.toml (no meeting content), logs (no
  meeting content beyond names; say so).
- Backend without the key (keyring locked): the API answers 423 with a clear message; the UI
  offers the recovery key.

## 10. Echo cancellation uses the chosen mic (added by Corey)

`audio/echo_cancel.py` loads the module with `capture.props` naming no target, so WirePlumber
connects it to the default source (here `easyeffects_source`, RNNoise before the AEC); picking a
mic in Mnemosyne has no effect on it.

- `load_command()` / `EchoCancelManager.start()` take an optional source node name and put
  `target.object = "<node.name>"` and `node.dont-reconnect = true` in `capture.props`.
- Pass the selected input device's node name (devices are remembered by node name); never the
  echo-cancelled source itself. No mic selected: the default source, as today.
- Selected mic changes while echo cancellation is on: restart the module with the new target,
  but never mid-recording (apply at the next recording start).
- Status/UI: show which mic the echo canceller uses, next to the Enable button.
- Tests: `load_command` with and without a target; restart on target change (fake `pw-cli`).
- Verify offline with `pw-link -l | grep mnemosyne_aec`: its capture input comes from the chosen
  mic. Never play audio.
