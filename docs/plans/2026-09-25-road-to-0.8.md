# Road to 0.8.0

Agreed 2026-09-25. main already holds, unreleased: the live copilot, the first-run setup wizard,
one `uiState.view` with a grouped header and tabbed Settings, the live-threads setting, and the
0.7.1/0.7.2 fixes plus readable dropdowns (`4cbb89d`). This batch makes 0.8.0 about two things:
**never lose a meeting** (what went wrong in 0.7.x) and **a finished copilot**.

One commit per item on main, each with its tests, in this order. Checks before every commit:
`uv run ruff check . && uv run ruff format --check . && uv run pytest` (in `backend/`),
`bash scripts/gen-api-types.sh --check` (run without `--check` after changing a model),
`pnpm check`, `pnpm test:e2e`, and `cargo check` for Rust changes (resource-capped:
`systemd-run --user --scope -p MemoryMax=8G -p CPUQuota=400% cargo check -j 4`).

Constraints (see CLAUDE.md): never play audio on this machine; test live features offline by
feeding segments in. Other Claude sessions may share this checkout: commit files by name, never
`git add -A`/`git commit -a`.

## 1. Recover interrupted recordings

**Problem.** If the app, backend or desktop dies while recording (the 0.7.0 freeze forced
restarts), the session stays `recording` forever: `AppContext.startup()`
(`backend/mnemosyne/api/context.py`) never looks at it, and the per-device WAVs in
`recordings_dir/<session_id>/<session_id>_device_<id>.wav` are never encoded or mixed. pw-record
killed with SIGKILL leaves a WAV whose RIFF/data sizes are wrong (often 0), so tools may read
it as empty.

**Do.**
- At recording start (`routes/audio.py::start`), write `recording.json` next to the WAVs:
  `[{device_id, device_name, is_output, path}]` (device ids change after a reboot, so the source
  kind must be saved then, not looked up later). Remove nothing at stop; it is tiny.
- New `services/recovery.py`:
  - `repair_wav(path) -> bool`: if the RIFF or data chunk size disagrees with the file size,
    rewrite both sizes in place (header is 44 bytes for pw-record's s16 WAV; parse chunks rather
    than assume, and skip files without a `data` chunk). Returns whether audio remains.
  - `find_interrupted(repo, active_ids) -> list[Session]`: sessions whose status is `recording`
    (or `encoding`) and not in `ctx.active_recordings`.
  - `recover(ctx, session_id)`: repair each WAV, build `Recording`s from `recording.json`
    (fallback when missing: source `mic` for all, named "Recovered track N"), mix with
    `mix_audio_files` exactly like `stop`, `set_audio`, status `created`. Sessions with no
    usable audio become `error` with a clear message.
- In `startup()`, run recovery for every interrupted session as a job (`kind="recover"`) so
  progress shows; afterwards emit a `recovered` event `{session_id, name, seconds}`. Honour
  `auto_transcribe` afterwards like a normal stop.
- Frontend: a toast per recovered meeting ("Recovered 'Standup' (23 min) after an interrupted
  recording") with a Transcribe button when it was not auto-transcribed.

**Tests.** `test_recovery.py`: a WAV with zeroed sizes is repaired and readable by `soundfile`;
a startup with a `recording` session plus WAVs ends `created` with audio and a mixed file; one
with no WAVs ends `error`; an active recording is left alone. No real pw-record needed.

## 2. AppImage smoke test in CI

**Problem.** 0.7.1 shipped an AppImage whose WebKit crashed on the first `<audio>` element
(no GStreamer plugins bundled). Nothing in CI starts the built app.

**Do.** New job `smoke` in `.github/workflows/release.yml` after `bundle`, needing the
`mnemosyne-linux` artifact, on `ubuntu-22.04` (the oldest target):
- Static check: extract the AppImage (`--appimage-extract`), fail unless
  `usr/lib/gstreamer-1.0/` contains `libgstautodetect.so`, `libgstplayback.so`,
  `libgstpulseaudio.so`, `libgstwavparse.so`, `libgstogg.so`, `libgstopus.so`, and
  `apprun-hooks/linuxdeploy-plugin-gstreamer.sh` exists. Resolve `autoaudiosink` through the
  bundled `libgstreamer` with the bundle's `GST_*` env (a 10-line ctypes script:
  `gst_init`, `gst_element_factory_find`), so an ABI mismatch fails too.
- Runtime check: `xvfb-run` the AppImage with `MNEMOSYNE_BACKEND_URL` (add this env override to
  lib.rs if absent: skip spawning the backend, point the window at the given URL) aimed at a
  demo backend started from the checked-out source (`tests-e2e/start-backend.sh`), with one
  imported session that has audio. Drive it with `tauri-driver` + WebdriverIO, or, simpler,
  add a hidden `MNEMOSYNE_SMOKE=1` mode in the frontend that opens the first session, creates the
  player, calls `play()` on a muted element and writes `ok`/the error to the backend
  (`POST /api/system/smoke`), then quits. Fail if no `ok` within 60 s or the log contains
  "web process terminated". Audio in CI goes nowhere (no sound server); the element must be
  muted anyway.
- Also run the static check on `workflow_dispatch` builds.

## 3. Live transcript backs off under load

**Problem.** Live transcription is capped at 2 threads (0.7.1) but a slow CPU or a busy GPU box
can still fall behind; ticks then pile up and the desktop stutters.

**Do** (in `transcription/live.py`, `LiveTranscriber.run`):
- Measure each tick's wall time. If a tick takes longer than `interval`, double the effective
  interval (cap 4× the setting); after five consecutive fast ticks (< interval/2), halve it back
  toward the setting. Read `/proc/pressure/cpu` (`some avg10`) when present; above 40, treat the
  tick as slow too.
- When the interval changes or the live transcript is behind by more than 30 s of audio, emit a
  `live_status` event (the existing `_status` helper) such as "Live · slowed down (CPU busy)";
  back to "Live" when recovered. Never stop the recording, never drop audio: the final job
  covers everything anyway.
- Setting `live_adaptive: bool = True` (Settings → Recording → Live, next to CPU threads).

**Tests.** A fake transcriber whose `transcribe` sleeps: the interval grows, is capped, and shrinks
after fast ticks; a fake pressure file triggers slow-down; status events are emitted once per
change.

## 4. Backend log file + Copy diagnostics

**Problem.** The backend's stdout/stderr are inherited by the Tauri shell (`lib.rs` ~l.368), so an
AppImage started from the desktop keeps no backend log at all; Corey has been pasting terminal
output instead.

**Do.**
- Backend: add a `RotatingFileHandler` (2 × 2 MB) at `<data_dir>/logs/backend.log` in
  `cli.py` (both `main()` and the `main.py` shim path), level INFO, same format as the console.
- `GET /api/system/diagnostics` → `{text: str}`: app/backend versions, Python, OS
  (`/etc/os-release` PRETTY_NAME), desktop session type, GPU (torch.cuda if already imported,
  else `nvidia-smi -L` with a 2 s timeout), install kind (AppImage/deb/rpm/Flatpak/dev from
  env), transcriber/diarizer/provider names, active jobs, the settings as TOML with every
  secret-like key (`*token*`, `*key*`, `*secret*`, `*password*`, `*_url` credentials, `hf_token`)
  replaced by `"<set>"`/`"<unset>"`, and the last 200 lines of `backend.log`. Redact the user's
  home directory to `~`.
- Settings → General: "Copy diagnostics" (copies, toast "Copied, paste it into an issue") and
  "Open log folder" (Tauri `opener` on the Rust log dir; show the path in the browser build).

**Tests.** Diagnostics never contains the value of any setting whose key looks secret (set every
secret field to a sentinel and assert absent); log tail present; home redacted.

## 5. Copilot notes that survive the meeting

**Problem.** `ctx.copilot_notes` lives only in memory; `start` pops it and nothing saves it, so
the notes vanish at stop or on a backend restart, and the final summary never sees them.

**Do.**
- Persist: `sessions.copilot_notes` JSON column (migration in the repo's schema step), written by
  `copilot_runner` on every update and once more at cancel. `GET .../copilot` reads the DB when
  not in memory.
- Summary tab: a collapsed "Live notes" card (so far / decided / to do / open) when notes exist.
- Summarization: pass the notes to the summary prompt as "Notes taken live during the meeting
  (may be incomplete; the transcript wins)". Keep `source_hash` from the transcript only.
- Tasks: when the meeting ends, copilot to-dos that the final summary has no close match for
  (normalised text, token-set ratio < 0.6) are appended as `ActionItem`s with `source="live"`
  so they appear in Tasks; re-summarize keeps them unless the user ticked or deleted them
  (reuse the carry-over logic in `services/tasks.py`).

**Tests.** Notes persist across a new `AppContext` on the same data dir; the summary prompt
contains them (FakeProvider records prompts); unmatched to-dos become tasks, matched ones do not.

## 6. Summary items link to the transcript

**Problem.** Decisions, action items and open questions are free text; checking one means
scrolling the transcript.

**Do.**
- Ask the model for a source per item: extend the JSON schema in `summarization/prompts.py` so
  `decisions`/`open_questions` items may be `{text, at}` and `ActionItem` gains `at: float | None`
  (seconds, from the `[mm:ss]` stamps already in the transcript given to the model). Parse both
  old (plain string) and new shapes; models stay `list[str]` for decisions/questions by adding
  parallel `decision_at` / `question_at: list[float | None]` so old data keeps working.
- Validate: drop an `at` outside the meeting or not within 20 s of a segment start; snap to the
  nearest segment start.
- UI: a small timestamp link after each item (same style as chapters); clicking switches to the
  Transcript tab, scrolls to and highlights the segment, and seeks the player (which creates the
  `<audio>` lazily since 0.7.2).
- Map-reduce summaries: part summaries keep absolute times; the merge keeps them.

**Tests.** Parser accepts both shapes; out-of-range stamps dropped; snapping; e2e: demo summary
with stamps, click a decision → Transcript tab with that segment highlighted. Update
`demo.py` canned replies (the e2e depends on exact strings, update specs together).

## 7. Ctrl+K command palette

**Do.** `components/CommandPalette.svelte`, opened by Ctrl+K (and a header button), handled in
`controller.svelte.ts` next to the existing Ctrl shortcuts.
- Sources: meetings (name, date; fuzzy on name, attendees), people, topics, open tasks, views
  (Ask, Tasks, People, Topics, Digest, each Settings tab) and actions (Start/stop recording,
  New session, Import, Ask "<query>", Search transcripts "<query>").
- Fuzzy match in the frontend (no dependency; subsequence scoring with word-start bonus), max
  50 results, arrow keys + Enter, Esc closes, focus returns to where it was. Data comes from
  stores already loaded; people/topics lists are fetched once on first open and cached.
- Recent picks first when the query is empty.

**Tests.** e2e: Ctrl+K → type part of a meeting name → Enter opens it; "settings ai" opens the AI
tab; "Ask budget" opens Ask with the question filled.

## 8. Diarization (from the parallel "Nemotron 3 diarization evaluation" session)

**Status (2026-09-25): in progress, not yet planned into 0.8.0.** The other session is trying
NVIDIA Nemotron-3-Diarization (Streaming Sortformer v2, up to 8 speakers) for the final pass.
Model cards: offline DER ~11% vs ~20% for pyannote community-1 (AMI SDM, DIHARD III,
AliMeeting); about 670 MB VRAM on the 2080 Ti. The synthetic espeak bench is not meaningful
for it (it merges the two robot voices). A DER comparison on 4 AMI meetings decides whether
it goes in. Live (streaming) would come later.

Files owned by that session, uncommitted on main: new `transcription/diarizers/nemotron.py`,
`tests/test_nemotron.py`; edited `transcription/registry.py` and `config.py` (a comment on
`diarizer`). **Do not touch or commit them from this batch.** Items 3 and 5 add settings to
`config.py`: commit only our hunks (`git diff config.py` → edit the patch →
`git apply --cached`), never the whole file, while that edit is uncommitted.

If the numbers hold: its own commit, opt-in `diarizer = "nemotron"` behind the `Diarizer`
Protocol, bench numbers in the message. Packaging is Corey's decision and blocks shipping it
to users: NeMo from git main (PyPI 3.0.0 lacks RoPE; pins lightning<=2.4, omegaconf<=2.3,
packaging<25; +62 packages) as a new extra, or NVIDIA's NeMo-Speech.cpp (GGUF; CPU, CUDA or
Vulkan). Without a packaging decision, 0.8.0 ships without it.
