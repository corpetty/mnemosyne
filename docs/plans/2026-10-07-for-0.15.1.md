## 1. Fall back to XWayland when Wayland fails at startup (src-tauri/src/main.rs)

Native Wayland is the AppImage's default since d9a73f9; tauri#8541 was a crash at startup on
Wayland in AppImages. Before choosing Wayland, main.rs writes a marker
(`<config>/com.corpetty.mnemosyne/wayland-starting`); lib.rs removes it once the window has been up
for a few seconds, and on exit. A marker found at launch means the last Wayland start died: write
`display-x11` (sticky), log it, start on XWayland. `MNEMOSYNE_WAYLAND=1` forces Wayland and clears
the sticky choice; `MNEMOSYNE_X11=1` still forces XWayland.

## 2. Smoke test the AppImage on Wayland in CI (scripts/smoke-appimage.sh, smoke.yml)

The smoke test runs under xvfb (X11), so the new default path is never started in CI. A third
matrix flavour, `wayland`, runs the normal AppImage under a headless Weston
(`SMOKE_DISPLAY=wayland`), no X display at all, and checks the log says it ran on Wayland.

## 3. Backend memory when idle (backend)

The idle backend held ~7 GB (PSS 6.9 GB) with 21 PyTorch inductor compile workers. Set
`TORCHINDUCTOR_COMPILE_THREADS=1` before torch is imported (compiles in-process, no worker pool).
After `ModelService.unload`: `gc.collect()`, `torch.cuda.empty_cache()` when torch is loaded,
glibc `malloc_trim(0)`, and log the process RSS before and after so the effect shows in
backend.log. Measuring with real models needs Corey's OK (loads models, runs a transcription).

## 4. Restore an earlier summary (records, RecordsCard)

Versions keep `{transcript, summary}` (hashed for records). Add a `summary_data` column to
`session_versions` (outside the hash), filled by `keep_version`; versions also differ when only
the structured data changed, so tag-only edits leave a version. `POST
/api/sessions/{id}/versions/{vid}/restore-summary` puts that summary (text and data) back, keeping
the current one as a version ("restored"), history `summary_restored`. RecordsCard: "Restore this
summary" per earlier version that has one.

## 5. Rename or merge a tag across meetings (topics)

`POST /api/topics/rename {from, to}`: in every meeting the person may change, the topic (matched
case-insensitively, as the Topics view groups them) becomes `to`; duplicates merge. Also kept as
`settings.topic_aliases` so new and re-made summaries use the new name. Topics view: rename per
topic (typing an existing topic merges).

## 6. Edit tasks from the Tasks view (routes/tasks.py, TasksPanel)

`PATCH /api/sessions/{id}/action-items/{idx}` takes optional `text`, `owner`, `due` besides
`done`; changing text/owner/due counts as a summary edit (`edited_at`). TasksPanel: edit inline.

## 7. Revise the summary with an instruction (pipeline summarize)

`POST /api/sessions/{id}/summarize` takes `revise: str`: the model gets the current summary (with
any hand edits) and the instruction ("shorter", "focus on decisions") besides the transcript, and
writes the summary again. Done ticks, issue links, due dates carry over as usual. SummaryView: a
"Revise…" field next to Re-summarize.
