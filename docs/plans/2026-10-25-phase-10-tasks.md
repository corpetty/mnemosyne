# Phase 10 tasks: guest notes without a host to run

Status: built 2026-10-25, unreleased. The design is "Phase 10" in 2026-10-12-hashseq-collaboration.md;
this file is the build order, drafted against a67739a and checked against the code.

Decided while planning (from Corey's answers and safe defaults): a separate `mnemosyne-link rooms`
process (guest notes must not need remote access on); the guest page's CSP lists relay origins
explicitly (n0's, ours once it runs, configured ones), never `https: wss:`; `auto` opens a
Cloudflare quick tunnel when iroh cannot be used (Funnel first when Tailscale runs); `cloudflared`
pinned by the SHA-256 digests GitHub publishes for release assets; the browser keeps the sealed
snapshot only; the testing-relay label also shows on the guest page.

## Corrections to the design (from reading the code)

- **C1 Embed the publish host, do not extract a crate.** rooms.rs/live.rs are tied to axum and the
  host's error/store/config types. `link/` takes `mnemosyne-publish-host` as a path dependency and
  runs `App::new` + `router` on 127.0.0.1:0 (rate limits off: every guest arrives from loopback;
  an upload token only the backend knows). The bridge talks to it as to any publish host.
- **C2 A second sidecar process**, `mnemosyne-link rooms`, supervised like `home`, started on demand
  by `guest_notes.start`/`resume`, stopped when no iroh/tunnel room remains; control ops
  `room_start {room, relay?}` → `{endpoint_id, relay}`, `room_stop`, `room_list`; per-room keys in
  `<data_dir>/guest_rooms/keys/<room>.key` so the link survives restarts.
- **C3 Pin the home relay**: pick one relay per process (`home_relay_status()` of a throwaway
  endpoint when several), bind each room endpoint with `RelayMode::Custom([pick])`, store it.
- **C4 One bi stream per guest**, frames `u32 len || tag (0 text, 1 binary) || payload`, proxied to
  `ws://127.0.0.1:<port>/live/<room>`; close codes become QUIC app closes.
- **C5 CSP connect-src** adds the relay origins (backend from `remote_relays`, publish host from
  `PUBLISH_RELAY_ORIGINS`, the Pages copy by meta tag: n0 + ours).
- **C6 Vite base `./`** and code splitting, so the page works at `/n/` on every origin and the iroh
  module is a lazy chunk.
- **C7 Link format 2** `#2.<room>.<key>.<endpoint>.<relay host>` (split at the first four dots);
  loopback relay hosts use http/ws (e2e). Iroh first (8 s after the wasm is up), then the host's
  wss only when the path carries `/n/<room>`; `since` per transport.
- **C8 Mirror = a second Bridge** on the same session; the tunnel needs no second room (it exposes
  the same loopback host). New `guest_rooms` columns: transport, endpoint_id, relay, public_url,
  mirror_host_url, mirror_token, mirror_last_seq.
- **C9 `guest_transport` auto|iroh|tunnel|host**; auto = iroh, else tunnel, else host; mirror
  whenever a host is configured.
- **C10 Tunnels** in services/tunnel.py: Funnel (`tailscale funnel --bg --https=443 <port>`) when
  Tailscale runs, else `cloudflared tunnel --url http://127.0.0.1:<port> --no-autoupdate` (URL from
  stderr); cloudflared via services/downloads.py into `<data_dir>/tools/`.
- **C11 Page origin** `https://corpetty.github.io/mnemosyne/n/` (setting `guest_page_url`); a tunnel
  or a mirror host gives its own origin.
- **C12 Awake** while an iroh/tunnel room is live.
- **C13 e2e** with a plain-HTTP dev relay (`mnemosyne-link dev-relay`, feature `dev-relay`).
- **C14 guest-wasm in CI**: clang-18 pinned, `--cfg getrandom_backend="wasm_js"`, same rustc and
  wasm-bindgen as notes; output `guest/pkg/` uploaded on every run and committed from the artifact.
- **C15 IndexedDB**: the last sealed snapshot + expires/ended_at per room; deleted on 4410, expiry
  or a key that does not open it.
- **C16 API/records** gain transport, relay, relay_kind, public_url, mirror_host_url, page_origin.
- **C17 Loopback requests** with `trust_env=False`.

## Found while building

- Frames had to fit a full snapshot (8 MiB + 64 KiB), not only the 2 MiB notes frame; both frame.rs
  copies (link and guest-wasm) carry that limit and must match.
- The guest page's meta CSP moved to the GitHub Pages copy only: under the servers' header CSP it
  also blocked loopback relays (the e2e's http dev relay). The backend and the publish host keep
  their header CSP; `PUBLISH_RELAY_ORIGINS` adds relay origins there.
- `/n` redirects to `/n/` so the relative assets (Vite base `./`) resolve.
- Rooms are served again after a rooms-sidecar restart (the backend re-sends `room_start` with the
  stored key and relay).
- A test once opened a real Cloudflare quick tunnel; conftest now stubs tunnels (`no_tunnel`).
- Presence is not shared between the iroh room and the host mirror: guests on one transport do not
  see guests on the other.
