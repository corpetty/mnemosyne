## Goal (Corey, 2026-11-09)

A teammate who has only a Mac laptop runs Mnemosyne natively:

- their own library on the Mac;
- records the mic and the system audio, the Zoom app included;
- transcribes and labels speakers on the Mac;
- shares with Corey through People (contacts, phase 8) and the library features.

Apple silicon only. Builds are unsigned for now (there is no Apple Developer account). Signing and notarization
are planned for later but nothing depends on them. CI on GitHub macOS runners covers build, backend tests and a
smoke test. Real capture is tested only by the teammate.

## What I found that changes the old plan

1. **The minimum version should be macOS 15.4, not 14.2.** Meeting audio is Ogg Opus (`.ogg`, `audio/ogg`:
   api/routes/audio.py:637). WebKit only plays Ogg on **macOS Sequoia 15.4+**: the Safari 18.4 release notes tie
   Ogg/Opus/Vorbis support to 15.4, not to Sonoma, even though Safari 18.4 also ships on Sonoma. Without 15.4,
   playback, clips and the smoke test's `<audio>` (src/lib/app/smoke.ts) all fail in WKWebView. Every Apple silicon
   Mac can run 15.x. The other way is to remux to CAF/WebM or transcode for old systems; I did not plan that.
2. **Security issue: sharing with people breaks open on macOS.** The link sidecar marks tunnelled connections
   (paired computers, *contacts* = other people) by connecting to the backend from 127.0.0.2
   (link/src/lib.rs:59-88). The backend then always demands a token for them (api/auth.py:49,73-74). macOS does not
   route 127.0.0.2 to lo0 unless someone runs `ifconfig lo0 alias`, so the bind fails. The code then falls back to
   127.0.0.1 with a warning (lib.rs:70-87) and the backend treats a contact as **this machine**: no token is needed
   and the contact acts as the tokenless desktop owner. On the teammate's Mac, Corey (a contact) would get owner
   access to their whole library. This must be fixed before sharing is used on a Mac: use a separate loopback port
   for tunnelled traffic, and fail closed rather than fall back. (verify: a cargo test on the macOS runner that
   binding 127.0.0.2 fails.)
3. **The `sqlcipher3` wheel now has macOS arm64 builds.** The base install fails today only because of
   `sqlcipher3-binary` (backend/pyproject.toml:24), which has no macOS wheel and no sdist. coleifer's `sqlcipher3`
   0.6.5 ships self-contained wheels with SQLCipher statically linked, including `cp313 macosx_11_0_arm64`, and
   it provides the same `sqlcipher3` module (storage/sqlite.py:683-697). So encryption at rest can work on the Mac.
   I checked the lock: every other base and `onnx`-extra package has a macOS arm64 cp313 or universal wheel
   (onnxruntime 1.30.0 is `macosx_14_0_arm64`; sherpa-onnx 1.13.8, numpy, cryptography, tokenizers and uvloop too).
   The only packages with no Mac wheel are in the `gpu` extra: torch/torchaudio +cu128, triton, nvidia-*, and
   cuda-bindings. The Mac skips that extra.
4. **Phonon-2 has native macOS arm64 code.** fermion-research 0.2.11 is a `py3-none-any` wheel that carries
   `libphonon2_*-macos-arm64.dylib` and an MLX path (`_native_mlx/libphonon_mlx-macos-arm64.dylib`, extra `mlx`).
   Its requirements file, though, pins `torch==2.14.1+cpu` with Linux hashes (phonon-requirements.txt:736). The
   Mac needs a second pin set. Phonon on the Mac is a separate task, not part of Phase 0.
5. **llama.cpp b11323 has a macOS build**: `llama-b11323-bin-macos-arm64.tar.gz`, 11,827,755 bytes,
   sha256 `f0d3eeed71dd9c76d83226d4571c4593dfe596daa3e614ec94980e32fae4ad8a` (from the GitHub API digest), with
   Metal. Today the Mac would download the *Ubuntu* CPU tarball (local_llm.py:161) and fail with an exec-format
   error. The same bug is in cloudflared: tunnel.py:51,67-71 maps `arm64` to the **linux**-arm64 binary.
6. **cpal ≥ 0.17 records system audio on macOS** with a Core Audio process tap and an aggregate device (cpal PR
   #1003, merged 2025-09-24; `src/host/coreaudio/macos/loopback.rs`, on `objc2-core-audio`). It taps one *output
   device* by UID, though. A meeting tool wants a **global** tap (all processes, whichever output they use), so that
   switching to AirPods mid-call does not lose the far end. Write our own tap (about 300 lines on the same
   `objc2-core-audio` bindings, using cpal's loopback.rs and AudioCap/audiotee as references) and use cpal for the
   microphone.
7. **TCC and unsigned builds.** An ad-hoc signature (`codesign -s -`) pins the TCC grant to the binary's cdhash.
   Every update changes it, and the stored grant then fails, sometimes silently with no new prompt. A **stable
   self-signed code-signing certificate** (kept as a CI secret) pins the grant to the certificate and the bundle ID
   instead, so grants survive updates, and it costs nothing. Gatekeeper still blocks the first open: since Sequoia,
   right-click > Open no longer bypasses it. The tester uses System Settings > Privacy & Security > Open Anyway, or
   `xattr -dr com.apple.quarantine /Applications/Mnemosyne.app`.
8. **A Finder-launched app's PATH is `/usr/bin:/bin:/usr/sbin:/sbin`**, so a Homebrew ffmpeg is never found.
   ffmpeg and ffprobe have to ship inside the app (they are used by mixer.py, capture.py:264, parts.py:61/84,
   clips.py:61, composed.py:22 and bench.py).

## The capture sidecar: design

`mnemosyne-capture`: a new Rust crate `capture/`, built like link (scripts/build-capture.sh), shipped as a Tauri
`externalBin`. It keeps **pw-record's contract**, so nothing downstream changes: the live transcript's WavTail,
level meters, CaptureHealth (audio/health.py: "silence still grows the file"), recovery's `repair_wav`,
`convert_to_opus`, and the manifest.

- `mnemosyne-capture devices`: JSON in the backend's `AudioDevice` shape. `id` is the Core Audio AudioObjectID
  (an int, like a PipeWire id). `name` is the device **UID**, which is stable and is what the UI saves.
  `description`, `media_class` is `Audio/Source` or `Audio/Sink`, plus `default`. There is one extra entry,
  `{id: 1, name: "system", description: "System audio (all apps)", media_class: "Audio/Sink"}`. id 1 is
  kAudioObjectSystemObject, so it never collides with a real device. Listing needs no TCC permission.
- `mnemosyne-capture record --target <uid|system> --rate 48000 --channels 1 [--log <file>] <out.wav>`. It writes
  `wav_header()`'s placeholder header (capture.py:86-98), then appends s16 PCM and flushes about every 100 ms. On
  SIGTERM or SIGINT it fixes the sizes and exits 0 (capture.py:287-296 sends SIGTERM, waits 5 s, then kills).
  Mic: cpal input stream. System: a global `CATapDescription` (stereo global tap excluding our own pid, mixed to
  mono), wrapped in a private aggregate device with drift compensation. It **resamples to a fixed 48 kHz**
  (rubato). AirPods switch to HFP (16/24 kHz) when a call opens the mic, and a rate change mid-file would break the
  single WAV. If the device disappears, it exits non-zero with a stderr/log line, and health reports "stopped".
- `mnemosyne-capture doctor`: JSON for diagnostics. It gives the macOS version, mic authorization
  (AVCaptureDevice status), default input and output and their rates, whether taps are supported, the app's
  signing kind if it is passed in, and the counts of exact-zero buffers per source from the last run's log.
- `mnemosyne-capture apps` (P3): processes with running input, from `kAudioHardwarePropertyProcessObjectList` +
  `kAudioProcessPropertyIsRunningInput` + bundle id. This feeds auto-record (streams.py `KNOWN` gets `us.zoom.xos`
  etc.).
- A `--fake <tone|silence|file.wav>` source builds on every OS. That lets the WAV writer, the resampler and the
  stop/repair behaviour be tested in Linux CI, and backend tests drive the real binary if it is built.

Why a sidecar and not Python (`sounddevice` + the PyPI `catap`)? A recorder that is a separate process keeps
recording when the backend crashes, which is what recovery and the 15-minute grace (app_watch) rely on. Why Rust
and not Swift (audiotee is Swift)? One language for every sidecar, cpal and `objc2-core-audio` already cover what
we need, and CI already builds Rust. ScreenCaptureKit audio was rejected: it needs the "Screen & System Audio
Recording" permission, which Sequoia asks the user to re-confirm periodically. A Core Audio tap only needs "System
Audio Recording Only".

Permissions (Info.plist, via `src-tauri/Info.plist`, which Tauri merges into the generated one):
`NSMicrophoneUsageDescription`, `NSAudioCaptureUsageDescription` (taps; without it TCC **silently** denies),
`NSLocalNetworkUsageDescription` (iroh mDNS, LAN LLM servers). TCC charges the *responsible* process: the
app → backend (Python) → sidecar chain is attributed to Mnemosyne.app, the way commands run in Terminal are
attributed to Terminal (verify on the tester's Mac). The system-audio prompt appears when the IOProc is created
on the aggregate device (`AudioDeviceCreateIOProcID` blocks until it is answered; seen on the macOS CI runner,
2026-11-09), not when the tap or the aggregate is created. Until then the sidecar has opened no file and the
recording shows as stalled. A denied tap delivers zeros, which look exactly like silence. So the
sidecar logs "only digital silence from system audio for 60 s" and the doctor reports it. No hardened runtime and
no entitlements are needed while the build is not notarized. Notarization later needs hardened runtime plus
`com.apple.security.device.audio-input` on the app and every bundled Mach-O.

Backend side: `audio/capture.py` gets a small platform switch. `list_devices()` and `build_record_command()` call
`audio/coreaudio.py` on darwin (where `pw-dump`/`pw-record` are today). `levels.self_test` on darwin returns a
"play something and watch the System audio meter" result without playing anything. `recovery._recorders_writing`
accepts both recorder names through psutil.

## Decisions for Corey (with recommendations)

1. **Minimum macOS 15.4** (not 14.2): Ogg playback in WKWebView (WebKit's Safari 18.4 notes). All Apple silicon
   Macs can run it. Recommended. The other way is a CAF/WebM remux for older systems, which I did not plan.
2. **Signing for the trial: a stable self-signed certificate** (free; TCC grants survive updates) rather than
   ad-hoc (grants silently break on each update). Developer ID + notarization when there is an account. Recommended.
3. **ffmpeg source**: a pinned static macOS arm64 build from ffmpeg.martin-riedl.de (sha256 checked, quickest), or
   our own LGPL build in CI (more work, cleaner licence and provenance). Recommend the pinned download now and our
   own build before a wider release.
4. **Encryption at rest on the Mac**: available through `sqlcipher3` by platform marker (Linux stays on
   sqlcipher3-binary). The Keychain prompt for Python is acceptable for a trial. Recommend leaving it opt-in, as
   today.
5. **Engine defaults on the Mac**: transcriber auto → Parakeet int8 on the CPU (Phonon in P3, then auto picks it for
   English). Diarizer auto → onnx (sherpa-onnx), so no HF token is needed. No gpu extra; no CoreML at first
   **(guess: CoreML EP gains little on int8 Parakeet; measure before adding)**. Summaries via the built-in model
   with Metal (P3) or Ollama.
6. **Config file location on the Mac**: `~/Library/Application Support/com.corpetty.mnemosyne/config.toml`
   (`MNEMOSYNE_CONFIG_FILE` from the shell), not `~/.config`. Recommended (new installs only; Linux unchanged).
7. **What the UI says when the system-audio tap delivers only zeros** (likely a missing permission): this is a UI
   decision. The options are a capture-health hint ("System audio silent for 2 minutes; check Privacy & Security"),
   only in diagnostics, or nothing.
8. **Fix the tunnel-source issue on Linux too** (fail closed everywhere), not only on the Mac. Recommended: it is a
   silent privilege escalation wherever the bind fails.

## Risks

- **Process taps on real hardware**: the global tap with an aggregate device, drift, AirPods HFP rate switches, and
  silent zero buffers when permission is missing. Mitigation: resample to fixed 48 kHz, zero-buffer logging,
  doctor output, and the tester's checklist items 5-6.
- **TCC attribution through the Python middle process** (verify). If grants attach to the wrong process, the
  fallback is spawning the capture sidecar from the shell (Rust) instead of the backend, with the backend asking
  the shell. That costs about 2-3 days more.
- **Updates on an unsigned app**: App Management prompts, or grants reset on update. Mitigation: self-signing, and
  manual dmg as a fallback.
- **Sequoia's Open Anyway** flow is unfamiliar to testers, and there are reports of the button not appearing on
  15.1. The xattr command is the fallback.
- **The `Application Support` path has a space**: the venv, Phonon's venv and llama-server paths. uv writes /bin/sh
  trampolines for such shebangs; the smoke test exercises the base path.
- **APFS is case-insensitive**: Obsidian notes differing only in case would collide (low).
- **Local Network privacy (macOS 15)**: denying it breaks iroh LAN connections (relay still works) and LAN LLM
  servers. It is worth a line in the checklist if it is seen.
- **Documents folder TCC**: backups default to ~/Documents (prompt on first backup); a vault in Documents or
  iCloud Drive prompts too.
- **Merge conflicts** with the unmerged connections PRs in lib.rs and remote.rs.
- **Runner drift**: if `macos-15` becomes macOS 26 images, the smoke results still hold. If the runner image lacks
  audio devices, the device-list test is limited to the `system` entry.
