# Phase 11 tasks: the notes editor, live

Status: built 2026-10-25, unreleased. The design is "Phase 11" in 2026-10-12-hashseq-collaboration.md;
this file is the build order, drafted against 8be7160 (branch phase-11-notes-editor-live) and
checked against the code.

Decided while planning (safe defaults; the ones Corey may want to revisit are marked *):
- Shared UI lives in `src/lib/notes/ui/` and imports only from `src/lib/notes/` (never `$lib/stores`,
  `$lib/api` or toasts), so the guest Vite entry can use it; guest.css already sources `src/lib/notes`.
  App-only behaviour comes in through two provider objects (presence, inserts) built in
  `src/lib/app/notesPresence.ts` / `src/lib/app/notesInserts.ts` and `guest/src/presence.ts` /
  `guest/src/inserts.ts`.
- The guest page keeps its Undo/Redo buttons in the slim toolbar (phones have no Ctrl+Z); the
  desktop does not get them (today's split). *
- Chip URLs percent-encode their payload (`mnemosyne:person/Ada%20Lovelace`), so render.rs writes
  them bare and plain-text helpers never meet `<...>` destinations. Time chips use whole seconds.
- A notes action item's text keeps meeting-chip text (the title is what the task is about); only
  person and time chips are removed. *
- Member keys: `m<8 hex>` per notes connection (random at join), `g:<gid>` for a guest; the caret
  colour is a hash of the person (user id, else name; the gid for guests), not of the connection,
  so one person's two windows share a colour.
- Presence over the hub is coalesced, not dropped: a faster update replaces the pending one and
  goes out when its 100 ms window ends, so the last position always arrives.
- Guest META `clock` is `{part, offset, started_at}` (UTC ISO). The design's "counts from when it
  received it" breaks for a META that arrives inside an old snapshot; phones keep NTP time.
- In the Obsidian export, a task line that is an action item renders in the Notes section as a
  plain bullet (no checkbox): the Action items section lists it once, under `obsidian_task_scope`. *
- Tasks panel: for a notes item the edit form shows text and owner read-only ("Edit it in the
  notes") and keeps due; creating an issue from a notes item is not in v1 (an issue link set on a
  linked task still fans out to it). *
- FTS search stays on the stored markdown (SQL triggers index `sessions.notes` directly): chip
  text is in it, so names and titles are found; the `mnemosyne:` URLs are indexed like any link.

## Corrections to the design (from reading the code)

- **C1 Toolbars call one new primitive.** `EditorInput.setLineKind` TOGGLES (same kind = plain);
  "Turn into" must set. And `/` picks, chips and Table are edits the input layer cannot express
  today (SharedNotes/guest call `insertTable` on the doc directly). Add `EditorInput.command(fn,
  place?)` (the existing private `run`: beforeChange, undo entry, onLocalChange, update, caret)
  and `setLineKind(kind, {toggle: false})`. Everything else stays the existing commands.
- **C2 `/` triggers hook into commitNative, not keydown.** A typed character reaches the doc only
  in `commitNative` (input.ts). Add `onTyped?(char, caret)` called after a native insert of one
  typed character (never for a composition: compositionend commits with `typed = null`) and
  `interceptKey?(e)` called first in `onKeyDown` (Enter is a beforeinput command: preventing its
  keydown stops it). The menu tracks the trigger by the `/` character's element id, so remote
  edits do not move it.
- **C3 The two editors are two copies.** SharedNotes.svelte and guest/src/Notes.svelte each carry
  the same mount, toolbar, link prompt and comment glue (and differ: the guest has Undo/Redo, no
  Quote/Code). "One implementation" means extracting `NotesEditor.svelte` first; e2e keeps the
  accessible names (`Comment on the selection` exactly once on screen: Playwright is strict).
- **C4 Readers' presence is dropped today.** `receive_text` ignores presence from members that
  cannot edit, and `_presence` lists names only. New: `sel` accepted from every member, `typing`
  only from editors; hello carries `you.key`; `presence` gains `members: [{key, name, who,
  typing, sel}]`; caret moves travel as `{"type":"caret","key","sel"}`. Stored only on the
  in-memory Member, never logged.
- **C5 The bridge hears no room JSON.** Hidden members get frames only. Add `Member.presence_tap`
  (the bridge's): it receives `presence` and `caret` messages of members (never `guests`,
  `guest_caret` or `last_edit`), so owner-side carets can be sealed for guests without a loop.
- **C6 The host's broadcast channel can drop guests.** publish-host rooms share one
  `broadcast::channel(256)` for frames and presence and close a lagging listener (`CLOSE_LAGGED`).
  Carets at 7/s per person make a stalled phone lag and reconnect. Presence gets its own channel
  (lag = skip, not close) and a per-connection cap (10/s, burst 20, excess dropped silently). The
  embedded host in `mnemosyne-link rooms` gets it by the path dependency; deployed hosts need the
  new build (older ones still work, with the lag risk).
- **C7 Owner heartbeat stays.** Old (0.24) guest pages show gid `""` as "(host)"; new `o:<key>`
  envelopes are extra people there. Keep the `""` heartbeat every 10 s; new pages merge `o:`
  entries named like the host into the host's line. `o:` entries carry `typing` (guests never saw
  the owner typing before) and `gone: true` when the member leaves (old pages wait for the 30 s TTL).
- **C8 Mirror forwarding is per bridge, guests only.** Bridges are keyed `(sid, PRIMARY|MIRROR)`
  and share room id and key, so an envelope opens in both rooms. A bridge forwards the raw `0x02`
  envelope of a guest (gid matches `_GID`) to the meeting's other running bridges; the host never
  echoes a sender (live.rs `from == me`), and owner-side envelopes are never forwarded. Each bridge
  seals owner-side presence for its own room. Presence is not queued while disconnected.
- **C9 Time chips need the backend's part clock.** The frontend does not know the current part
  (Recording rows are written at stop, `recording.part` lives on the backend) and
  `recordingDuration` keeps counting across `restartCapture` (a new part). Add
  `{part, offset, started_at}` of the active part to StartRecordingResponse and the active
  recording status (audio.py, the model with `started_at: float`), from one backend helper that
  the guest META uses too.
- **C10 Combine renumbers every part.** combine.py orders the parts of BOTH meetings by recording
  time and numbers them anew, and joins the notes before cutting. Time-chip URLs of both meetings
  need the `(session, old part) -> new part` map, computed before the notes join; a meeting chip
  pointing at the removed meeting is retargeted to the combined one. Chip TEXT (`12:34`) is left as
  typed.
- **C11 Publishing does include notes** (`publishing.py`: `sel.notes`). plain_notes applies there.
  Ask and semantic search do not read notes; MCP prints `notes` from the API (mcp_server.py) and
  needs it; the summary hint (`shared_notes_hint(session.notes)` in pipeline.py) needs it; phase 8
  shares keep the markdown (the recipient's editor renders chips).
- **C12 Link hrefs are not filtered when rendered.** dom.ts sets `a.href = run.link` for any URL a
  peer wrote; a read-only editor is not contenteditable, so a `javascript:` link would run on click.
  dom.ts renders `href` only for http(s) and mailto; `mnemosyne:` runs become chips (`data-chip`,
  no href) and other schemes plain links without href.
- **C13 Comment ranges and fold results live in `shared_notes`, not `sessions`**, and there are five
  writers (`_fold_locked`, `_set_text_blocking`, `mark_comment_blocking`, sync_notes union and
  adopt). Notes items need state that is not derivable (follow, due, issue_url, task_id), so they are
  a stored column `sessions.notes_items` (JSON list of `NotesItem`), re-derived at each of those
  sites through one helper, and they travel in `SyncSession.notes_items` (state fields merged
  three-way per id; derived fields re-derived by the receiving fold). A derived write never
  `_touch`es (the notes markdown write next to it does); state writes do.
- **C14 Item ids must be hex.** Obsidian read-back parses `^m-([0-9a-f]+)`; task keys use `":" in
  key` to tell unlinked items. A notes item's id is the first 16 hex of its line id (the next 16 if
  all digits: identifier redaction), its key `<session>:<id>`; the full line id is kept in
  `NotesItem.line`. Summary ids are 8 hex, so lookups try summary items, then notes items.
- **C15 `idx` is everywhere.** TaskItem/TaskMention.idx index `summary_data.action_items`, and
  `list_tasks` maps rows by `(session_id, idx)`. Notes items get `idx = -(j+1)`, `source: "notes"`
  and TaskItem gains `item_id`; every idx-based writer (item_flags, `set_action_item_done`,
  `write_tick`, the PATCH idx route) refuses negative idx, and `list_tasks` maps by `(session_id,
  item_id)`.
- **C16 Done flows through the doc.** Ticking a notes item anywhere (Tasks, a linked mention's fan-out,
  reconcile, the vault read-back) writes `notes_items` AND appends a `set_kind` frame (sidecar,
  authored by the ticker, broadcast like `mark_comment`); the next fold derives the same value. One
  service function does both; task_links calls it for notes mentions. Readers may tick (as for
  summary items). On a `shared_from` meeting notes items are read-only (403 "Tick it in the notes").
- **C17 History would double over sync.** Each machine derives items; events travel in SyncSession.
  Only folds of frames appended on this machine log (`notes_task_added`, and `task_done`/
  `task_reopened` for ticks typed in the notes); sync union/adopt derive silently. "By" is the
  author of the frame that added the line or its task kind (the fold reply's `frame` index).
- **C18 notes-core changes stay out of the wasm.** notes-wasm links only `notes_core::client`
  (client.rs uses model and render, never doc.rs or api.rs), so the fold's `tasks` list and
  `set_kind` (doc.rs, api.rs) should leave `src/lib/notes/pkg` byte-identical. The wasm32 target and
  wasm-bindgen are not installed here: verify with the CI `notes` job; if it fails, take its
  `notes-wasm-pkg` artifact (`gh run download <run> -n notes-wasm-pkg -D src/lib/notes/pkg`), commit
  it, then `pnpm build:guest` (the guest bundles that wasm) and commit static/guest.
- **C19 The fake sidecar must learn it.** backend/tests/fake_link.py answers `notes doc` for every
  backend test; it needs `tasks` in every answer and the `set_kind` op, or the derivation tests
  cannot run.
- **C20 Vectors do not change.** guest_format.py only checks that PRESENCE and META are JSON; new
  optional fields (`sel`, `gone`, `clock`) need docstring updates only, not new vectors.
- **C21 Cost.** A sealed presence is ~285 bytes (256-byte padding), not 200: ten people at the limit
  is ~18 KB/s inbound per client. Still fine on relays.

## Tasks (tier, deps)

Files in brackets are what a task may edit; two tasks that can run at the same time never share a
file. Backend tests one file at a time (`cd backend && uv run pytest tests/<file> -q`); Vitest one
file at a time (`pnpm exec vitest run <file>`); `pnpm check` at 0 errors; ruff on touched files;
full e2e only in CI. Never play audio; tests never touch the machine. API reference edits are
collected in the docs task of each milestone (workers report their contract instead).

## Risks

- WebKitGTK: client rects of a collapsed range at a filler or line end, and the listbox's
  `aria-activedescendant` while the contenteditable keeps focus (the desktop app runs WebKit).
- IME: a `/` typed through an IME never opens the menu (by design); check that a composition that
  ends in `/` does not leave the menu half-open.
- The wasm module may still change bytes with notes-core edits (C18 loop costs a CI round trip).
- Notes items' `by` is approximate when several people edit one line between folds.
- Deployed publish hosts without task 10 keep the lagged-listener risk under many carets.
- Nothing of the guest path runs end to end locally (iroh in wasm is CI-built, phase 10).

## Found while building

- A time chip opens the transcript at its line, like a summary item's time, rather than seeking
  a player of its own: the player lives in the transcript view. It seeks without playing.
- Caret colour rule: a connection's member by `who` (user id, else name), a guest by its gid, an
  owner-side `o:<key>` entry by its name (so a guest sees one person's windows in one colour).
- `onTyped` fires only for single-character inserts. A keyboard that inserts a whole word at once
  (some Android ones) does not open a menu; the Insert button is the way there.
- `set_text` may reuse line ids, so notes items carry their state by text and owner when a stored
  item's line id has vanished (services/notes_items.py), not by id alone.
- The publish host has a separate presence channel with a cap of 10 per second per connection
  (excess dropped), so carets cannot make a listener lag out of the frames' channel.
- The harness (/dev/notes-editor) mounts NotesEditor with fake inserts and fake carets, for
  poking the menus, chips and overlay without a backend.
