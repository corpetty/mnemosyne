## 1. Code cleanup
- **Installable package.** Move `backend/src/mnemosyne` to `backend/mnemosyne` (flat layout),
  make it a real package in `pyproject.toml` (`[build-system]` hatchling, `package = true`,
  console script `mnemosyne-backend = "mnemosyne.cli:main"`). Rewrite every
  `src.mnemosyne` import to relative/`mnemosyne`. `main.py` stays as a thin shim for
  `uvicorn main:app` and the Tauri shell. Update `scripts/stage-backend.sh` (copy `mnemosyne/`),
  pytest `pythonpath`, ruff `src`, CLAUDE.md conventions.
- **Generated TS types.** `scripts/gen-api-types.sh`: export `app.openapi()` to
  `src/lib/api/openapi.json` and run `openapi-typescript` into `src/lib/api/schema.d.ts`.
  `src/lib/types/index.ts` re-exports schema types where they exist (keeps names stable);
  hand-written types remain only for WebSocket events. CI fails if the generated file is stale.
- **Split `+page.svelte`** (507 lines) into `AppHeader`, `SessionView`, `EmptyState` and a
  `lib/app/controller.svelte.ts` holding recording/remote-action logic.

## 2. Level meters + capture self-test
- Backend: while recording, compute RMS/peak per source from the growing WAV (reuse
  `WavTail`) every 200 ms and publish `levels` events `{session_id, levels: {device_id: {rms, peak}}}`.
  Idle meters: `GET /api/devices/{id}/level?seconds=1` records briefly and returns rms/peak.
- `POST /api/audio/self-test {sink_device_id}`: record the sink via the real capture command
  while `pw-play` plays a 1 kHz tone; report whether the tone was detected (FFT), its level,
  and which ports pw-record linked to (`pw-link -l`). Flags "recording the microphone" when
  linked to a source instead of `<sink>:monitor_*`.
- UI: meters next to selected devices on the Recording tab and in the footer while recording;
  "Test system audio" button with a clear pass/fail explanation.

## 3. Transcription progress
- Engines report stage + fraction: Parakeet per VAD segment (duration-weighted), WhisperX by
  stage (load, transcribe, align, diarize, assign), per source. `JobContext.update(progress=...)`
  already exists; add ETA from elapsed/progress. UI shows a progress bar on the Transcript tab
  and the sidebar.

## 4. Glossary
- Setting `glossary` (one term per line, optional `wrong -> right` corrections).
- WhisperX: pass terms as `initial_prompt` (asr_options). Parakeet: no prompt support.
- Deterministic correction pass (case-insensitive whole-word replacements from `->` lines)
  applied to final transcripts; optional LLM correction step (`glossary_llm_correct`) that
  fixes proper nouns against the glossary in batches, never altering meaning.
- Summaries/ask prompts include the glossary. UI: Settings textarea.

## 5. MCP server
- `mnemosyne-mcp` (stdio, official `mcp` Python SDK, FastMCP) that talks to a running backend
  over HTTP (base URL + token from env), exposing tools: `search_meetings`, `ask_meetings`,
  `list_meetings`, `get_meeting` (summary + transcript, paged), `get_action_items`.
- Docs with the exact `claude mcp add` line and Claude Desktop config. Tests with a fake backend.

## 6. Action items → GitHub issues
- Settings: `github_repo` (owner/name), `github_token` (secret), `github_labels`.
- `POST /api/sessions/{id}/action-items/github` with selected item indices → creates issues
  (title = item, body links back with meeting name/date, owner mention if it looks like a
  GitHub handle), returns URLs; records created issue URLs in `summary_data` to prevent duplicates.
- UI: checkboxes on action items + "Create GitHub issues" with confirmation listing the repo.
  Tests use httpx MockTransport.

## 7. Weekly digest
- `POST /api/digest {start, end}` (job): gather sessions in range, their summaries/decisions/
  action items, LLM writes a digest (markdown with links to each meeting's note), saved to
  the vault as `<subfolder>/digests/YYYY-Www.md` and stored in a `digests` table.
- Optional schedule: `digest_weekday` + `digest_hour`; the backend's periodic loop generates
  the previous week's digest once. UI: Digest view (header menu) with history and "Generate".

## 8. Playwright UI tests
- `tests-e2e/` with `@playwright/test`, chromium only. A fixture starts the backend with a temp
  data dir and a fake-engine mode (`MNEMOSYNE_FAKE_ENGINE=1` env switch in `registry.py` +
  fake provider) and Vite. Specs: import a file → transcript appears; rename speaker; edit
  line; search → jump; summarize → cards; ask → citation opens session; settings persist.
- CI job `e2e` running headless.

## 9. Auto-updates
- Generate a Tauri signing key (no password; file mode 600 at `~/.tauri/mnemosyne.key`;
  user told to back it up). `gh secret set TAURI_SIGNING_PRIVATE_KEY` (+ empty password secret).
- `tauri-plugin-updater` + `tauri-plugin-process`; `plugins.updater.pubkey` + endpoint
  `https://github.com/corpetty/mnemosyne/releases/latest/download/latest.json`;
  `bundle.createUpdaterArtifacts: true`. Release workflow uploads `latest.json` + signatures.
- UI: check on startup (and in Settings), prompt with release notes, download + restart.
  AppImage only (Tauri's Linux updater supports AppImage; deb/rpm users update via packages).

## 10. Flatpak
- `flatpak/com.corpetty.Mnemosyne.yml` on `org.gnome.Platform` wrapping the release binary +
  backend + uv. Permissions: pipewire socket, wayland/x11, network, `--filesystem=home` for the
  vault (documented), `--talk-name=org.freedesktop.Flatpak` for `flatpak-spawn --host` to run
  host `pw-record`/`pw-dump`/`pw-cli` (not in the runtime). ffmpeg from the
  `org.freedesktop.Platform.ffmpeg-full` extension.
- CI job building a `.flatpak` bundle with `flatpak-github-actions` and attaching it to releases.
  Local verification with `flatpak install --user` of the bundle.
